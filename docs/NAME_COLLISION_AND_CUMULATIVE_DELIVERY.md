# 名称冲突与多轮总交付门禁

## 触发及边界

技能、道具、角色等正式名称的翻译、改名及玩家混淆反馈，必须检查“异源同名”和正式术语同步。多轮返修后用户要求“全部修改、总交付”时，必须核对历轮变更并集。只处理已授权的语言和范围；只读检查其他语言不等于授权批量改名，不自动重译全表。

先从真实语言表显式提取名称定义 ID、中文、语言和译名，记录文件哈希、sheet、源行。不得从说明里的普通动词猜技能名。同一游戏、同一选择/引用范围的技能使用同一个 scope；不能把核心技能和终极技能拆成不同 scope 来规避碰撞。不同中文、相同标准化译名构成待裁决冲突；同一中文对应多个正常 ID 不自动算错。

## 执行入口

`scripts/run_name_collision_gate.py` 是只读 Agent CLI，不写 workbook，不接入产品后台，也不替代语义审校。JSONL 和报告均保存到项目私有 `_work`；禁止提交客户词条和语言包。

名称定义每行格式如下，ID 显式转字符串，语言代码可为 EN、ES、PT-BR 等项目实际代码：

```json
{"scope":"project:skills","id":"skill_1","cn":"风刃","lang":"EN","text":"Wind Blade"}
```

```powershell
python scripts/run_name_collision_gate.py names --definitions <名称定义.jsonl> --out <预检.json>
python scripts/run_name_collision_gate.py names --definitions <成品名称定义.jsonl> --require-distinct --out <最终冲突检查.json>
python scripts/run_name_collision_gate.py names --definitions <受影响成品名称.jsonl> --glossary <正式术语回读.jsonl> --require-distinct --out <术语同步检查.json>
```

标准化采用 Unicode NFKC、大小写折叠并忽略空格/标点；保留数字和重音。缺字段、空输入、空译名、同 scope/ID/语言的冲突定义不能作为“零问题”通过。`--glossary` 使用同样格式，要求受检定义均有一致的正式主译；术语必须从实际最终文件回读，不能拿预期修改字典充当同步证据。

默认每个未决冲突都阻断。经上下文确认可以共用时，可传 `--approvals <裁决.jsonl>`，每行包含报告中的精确 `fingerprint`、`decision: allow_shared` 和非空 `reason`。指纹绑定 scope、语言、全组 ID、中文和实际译名，数据改变后旧裁决失效。用户明确“全部分开”时必须传 `--require-distinct`，该参数禁止共用裁决生效。机器重名不等于已证实的语义错误；不得拿未运行的游戏配置作已确认事实。

## 名称修复闭环

1. 读取项目 brief、当前语言区域、正式术语及技能说明。按中文和定义 ID 建立独立名称，不按旧英文字符串全局替换。
2. 追踪同一中文名称的技能名、宠物被动、套装效果、特效皮肤、天赋和进阶分支等实际引用；区分“旋转切割”等普通动作描述，保留自然变格、数值、标签结构和固定换行。
3. 同步语言表与实际术语文件。主译更新、正式名称补录和自然语境变体分开记录；明确授权改名优先于默认只补空规则。补录数量不是错误数量。
4. 最终从文件重新抽取全部范围内名称执行冲突门禁；从实际术语抽取受影响定义执行同步门禁。完整回读、非目标对比和 Excel 打开验证仍按既有规范执行。
5. 默认保留用户熟悉且仍正确的一侧名称，修改冲突另一侧；但用户明确指定或说明语义要求优先。不为了让拼写不同而引入错误机制、技能层级或语言区域。

## 多轮总交付

每轮已验收的变更日志保存逻辑 scope、真实 ID、当前中文、语言、修改前后，并与文件/行号和版本证据关联。不同物理导出格式但相同逻辑修改只计一次；语言表与术语使用不同 scope。

```json
{"scope":"project:text","id":"skill_1","cn":"风刃","lang":"EN","before":"Old Name","after":"Wind Blade"}
```

按时间从早到晚传入每轮；最终 JSONL 必须从总交付表的实际修改明细回读：

```powershell
python scripts/run_name_collision_gate.py changes --round <第一轮.jsonl> --round <第二轮.jsonl> --final <总交付回读.jsonl> --out <累计交付检查.json>
```

门禁核对最早修改前与最后修改后，拦截漏掉前轮、最终译文陈旧、重复格、额外格、源文改变以及修改链断裂。同一轮的相同修改可来自多份同步格式；跨轮必须连续，不能靠 ID 复用旧中文。新译文允许从空白增加；回退到最初值的项目不列入净修改。该 CLI 验证表格导出结果，不自动生成 XLSX。

总交付主表每个真实文本 ID 一行，保留各语言最终值，仅改动语言标黄；术语同步另页，修改明细保留最初译文、最终译文和理由。必须分别报告 ID 数、语言单元格数、实际文件同步格数和术语补录数。人工核对黄底集合与净修改集合一致，不能只交最后一次 delta。

## 验收及生效范围

运行 `python -m pytest tests/test_name_collision_gate.py -q`。真实只读基准还应覆盖修复前可检出、修复后清零、漏前轮能阻断、累计交付完整可通过，并确认输入哈希未变。

当前为本仓库 Agent 执行规范和显式 CLI 门禁；普通旧命令不会自动获得新检查。未提交、未同步 Studio 时不得声称其他主机、旧线程或产品后台已经生效。客户端同屏展示、自然语言近义误用及正文变格仍需语义核查；该门禁不是全表深校或线上发布验收。
