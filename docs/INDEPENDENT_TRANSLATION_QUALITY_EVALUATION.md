# 独立翻译质量评估与反馈闭环

## 触发与边界

用户要求评估已交付译文、复盘深校质量或改进流程时执行。先重新读取源表、成品、当前术语表、项目 brief 和已验收历史；正式交付只读。评估者先审成品，再看旧建议，避免被旧理由锚定。未全量语义审读时，只报告实际覆盖范围。

## 三份独立证据

1. 确定性结构：逐格核对 ID、源列、目标完整性、程序 token、异常字符、标色与文件哈希。结构通过不等于语义通过。
2. 语言评估：固定样本覆盖非对白、连续对白和不同章节；定向扩查与固定样本分开统计。真实问题、风格偏好、上下文不足、误报分别记录。
3. 深校净效果：对照初译、建议、审计决定和最终译文。记录修复、保留问题、新引入问题和加重问题；修改量不作为质量得分。

每条问题至少包含原表行号、ID、语言、英语主源、中文参考、原译、建议译、理由、严重程度、样本归属与证据出处。相同单元格的多项问题按最高严重度计分，不能重复扣分。分值只是本轮诊断约定，不能用有目的抽样估计总体置信区间。

## 名称基线必须先于清空与初译

- 同批次已填译文的角色名行、姓名 sheet 和明确指定的角色表，也是名称证据；不能只加载外部术语表。先提取已批准名称，再清空工作副本中的目标列。
- 将这些明确的名称定义和最新术语表合入任务私有的临时术语快照，记录来源、行号与冲突；冲突须裁决，不能按读取顺序覆盖。名称定义不能由任意短文本或普通对白自动推断。
- 初译、深校和最终 cache-lint 使用同一合并快照；每行命中必须进入模型输入。正式术语表和原需求保持不变。
- QA 应记录“批准名称数、正文命中数、已复核候选数、真实遗漏数”。俄语变格、句中小写、自然代词省略与意大利语等源文有意保留的短语不能机械计错。
- 大文本加载器识别精确分类别名“角色 / 人名 / 人物 / character / character name / person / person name / name”。含 soft、generic、描述等复合类别不自动升级。泛角色类别中的普通亲属称谓保持语境约束；显式人名如 Grandma Ada 仍受名称约束。
- 英语主源时，强名称在中文出现、但官方英语明确省略时，不强制从中文补回。中文主源和 cn+en 仍按中文命中。不得拿其他英语句的代词替换名词来伪造豁免。

## 对白上下文与二次审计

- 非对白也不能只给孤立句：UI审计至少附同组件标题/相邻源与目标；物品说明附已验证的名称关联。不能因为没有对白scene就把context留空，再把可核实的对象误判为新增设定。若关联只由ID猜测而没有资源证据，仍标待确认。

- 对话包应提供完整话轮或场景摘要、可证明的 speaker/addressee、关系与年龄证据、前后源文，以及深校开始时的相邻目标译文。词性回指需要目标语言先行词，不能只凭英语 it 猜测。
- 相邻两行不能自动视作人物轮流发言。没有明确说话人字段时，以连续场景证据推断并注明不确定性；无法确定则保持或提出待确认项。
- 性别、称谓和人称修改必须指出具体证据。仅“likely female speaker”等猜测不足以接受改动；检查形容词究竟修饰说话者、受话者还是前置宾语。
- reviewer 的 reason 是待验证主张。auditor 必须收到主控补齐的源文、源模式、原译、上下文、token 和术语，不能只收到新译与理由，也不能信任 reviewer 自行回传的原译和上下文。
- 审计输入/提示版本变化后隔离旧 checkpoint；结构化文本仍只传已经拆出的纯文本槽。
- 对习语分别复述“谁对谁做什么”和情绪力度。表面意象更像英语并不代表译意更正确。独立盲审仍必需，单次模型 ACCEPT 不能替代主控判断。

## 回归和验收

- 抽样缺陷扣分指数不得命名为“整体翻译质量分”。目的性抽样、尚未审读单元格和待确认项不能被算作整体通过；风格表达能力、运行时体验与已确认缺陷分别报告。不得观察结果后调整公式以生成期望高分或低分。
- 使用 `python scripts/run_quality_diagnostics.py --cache-jsonl "<cache.jsonl>" --coverage "<coverage.json>" --target-langs "FR,DE" --out "<new-report.json>"` 校验范围。coverage 包含 `reviewed`、`unresolved` 的 `[physical_key, language]` 数组及 `sampling=purposive|stratified|census`。重复覆盖去重，超范围覆盖拒绝；完整覆盖也不自动生成质量分或发布通过。
- 物理行键用于精确回填，不可掩盖同文件同 sheet 下的资源 ID 冲突。冲突与完全重复分别报告，未经项目确认不得重命名、合并或按后写覆盖。参考 sheet 与正文 sheet 的相同 ID 不混为同一命名空间。
- 既有多语言诊断中，英语主参照不代表其已被证明为最新版本。中英实质冲突且目标跟随其中一版时，保留源版本待确认项，不擅自按照英语重译并扣目标错误。

- 机器规则同时给坏例和好例：同音异拼须被检出，正确变格、亲属称谓和英语省略须不被误杀。
- 审计传输回归要走真实 run_deep_proofread 调用链，并证明 reviewer 伪造的 current/context 不会覆盖主控证据。
- 再以真实问题做小规模语义回放，保留未拦住的案例。代码输入契约通过与模型语义有效性分别报告。
- 每次更新保存批次哈希、固定样本清单、裁决明细、评分公式和待判断项；后续批次复用同一指标口径，逐步积累匿名化回归案例，不把客户材料写进公共仓库。
- 提交与同步状态单独报告。本地改进未同步到产品时，不得声称所有入口已生效。

## 修复执行入口与验收

当用户授权修复后，原成品保留，另建批次修复目录；逐条记录原译、最终译、错误依据及保留项。全量结构门禁与定向问题语义复核分开，不把已知问题修复说成全表重新深校。

### 已批准姓名快照

在清空任何工作副本之前执行：

```powershell
python scripts/run_approved_name_snapshot.py --term-base "<术语表.xlsx>" --names-workbook "<原需求.xlsx>" --names-sheet "<姓名所在sheet>" --name-rows "<明确批准姓名的行号，以逗号分隔>" --target-langs "FR,DE,RU" --output "<私有_work/approved_terms.json>"
```

- 只接收执行者明确指定的姓名定义行，缺源文、缺目标语、行号越界或同名译文冲突均失败；不自动判断某句是否为姓名。
- 来源文件 SHA256、sheet、行号和 ID 随快照保存；外部术语表和正式需求不修改。新快照必须进入初译、深校和最终 cache-lint，不得在写回后才补。
- JSON 快照只能补已核实的自然语法变体，不能加入整句代词作为全局姓名变体。
- 主控确认的自然回指可以在单行缓存 `term_waivers` 中记录 `source/lang/target/cn/translation_source/context/reason`。必须完整匹配源文、译文与语境才生效，任一变化重新复核；不能让 reviewer 自报豁免，也不能删掉该行术语命中掩盖遗漏。

### 对白证据与语义回归

- `context` 中显式 `type=dialogue` 且有 `scene` 时，深校自动按文件、sheet、scene补齐源文和当前目标话轮；不超过48轮时提供整场，更长场景提供前后各8轮并明确 `complete_scene=false`。未知speaker/addressee保持unknown，不从相邻行强行推定。
- 场景证据进入 review签名和checkpoint；目标先行词变化后旧审校失效。结构化行仍只处理纯文本槽，不把整段JSON/标签重新带入模型。
- 对白/习语修改先做无源文、无审校理由的目标盲读，再审计。每个含此类修改的audit批次增加一次模型调用，不能声称无成本；盲读提供可追溯证据，不是语义正确证明。
- ACCEPT/REVISE必须提供 `semantic_check.source_meaning/final_meaning` 和三个布尔结果 `meaning_preserved/roles_preserved/tone_preserved`；字段缺失或存在false时阻断。REVERT以主控原译恢复，不能依赖模型重写。
- 模型仍可能自证错误。`semantic_regression.py`仅收录已确认且源条件明确的回归：如英语worry-your-head-about-it习语被法语写成担心头部。普通头部健康句及正确法语习语必须不被拦截。规则同时用于auditor返回值验证、客户端回退和cache-lint；拦截不自动生成新译文。
- 任意新规则须在 `fixtures/quality_regression.json` 添加坏例与好例，并通过真实调用链测试。不得把窄规则推广为全部习语已解决；工作区未提交、未同步时只在维护源执行入口生效。
