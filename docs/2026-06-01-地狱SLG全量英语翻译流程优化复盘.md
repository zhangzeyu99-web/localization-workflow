## 已确认的流程问题

### 1. Codex CLI 入口不稳定

Windows 下 `subprocess.run(["codex", ...])` 可能解析到旧的 `.cmd` shim，而不是当前 PowerShell 中的 `codex.ps1` 或新版 npm 安装入口。

已验证可用入口：

```powershell
D:\nodejs\node.exe D:\nodejs\node_modules\@openai\codex\bin\codex.js --version
```

该入口为 `codex-cli 0.135.0`，可用 `gpt-5.5`。

建议固化：

- 批量翻译脚本不要调用裸 `codex`。
- Windows 子进程显式调用 `node.exe + codex.js`。
- 每次大任务先跑 smoke test：`gpt-5.5` 返回固定 `OK` 后再分批。

### 2. Excel 读取方式必须顺序扫描

`openpyxl` 的 `read_only=True` 模式下，不要在大表中反复调用 `ws.cell(row, col)` 做随机访问。

建议固化：

- 提取输入：统一用 `iter_rows(values_only=True)`。
- 只在写最终 workbook 时使用普通模式 `load_workbook(final)`。
- QA 读回也用顺序扫描，避免验证阶段超时。

### 3. token 规则要覆盖真实游戏参数

本项目需要强保护的 token 类型包括：

- 数字参数：`{0}`、`{1}`
- 命名参数：`{item_name:2}`、`{map_position:4}`、`{time_format:3}`、`{shop_name_1}`、`{num}`
- 数值参数：`[v0]`、`[p1]`
- 富文本：`[color=#...]`、`[/color]`、`[U]`、`[/U]`、`[b]`、`[/b]`
- HTML 样式标签：`<br>`、`<br />`、`<a href='...'>`、`</a>`

不要把普通英文方括号标题一律当成富文本，例如 `[Hero Power]` 不是必须保护的源 token。

### 4. 结构 QA 要分层

推荐分成两层：

- hard blocker：空译文、中文残留、源/译 token 序列不一致、换行数不一致、响应缺行/多行/重复。
- soft warning：长度观察、标题大小写、术语派生形疑似不一致、英文自然性人工抽查。

本次术语抽查命中 `2812` 行，初筛 `23` 条潜在问题，多数是 `Ally -> Allies`、`City -> Cities` 等复数/派生形误报；实际未发现需要阻断的术语错漏。

## 可落地优化方案

### A. 固化 gpt-5.5 批处理入口

实现一个统一命令构造函数：

```python
CODEX_NODE = Path(r"D:\nodejs\node.exe")
CODEX_JS = Path(r"D:\nodejs\node_modules\@openai\codex\bin\codex.js")
cmd = [str(CODEX_NODE), str(CODEX_JS), "exec", "-m", "gpt-5.5", ...]
```

并在任务开始时写入 `runner_env.json`：

- `codex_version`
- `model`
- `smoke_test_result`
- `batch_size`
- `worker_count`
- `prompt_version`

### B. 先去重再翻译

本次 `8380` 行正文中只有 `6479` 个唯一中文文本。

如果先按中文文本去重，可少翻 `1901` 行，节省约 `22.7%` 的生成量。

推荐流程：

1. 建立 `source_text -> keys[]` 映射。
2. 对唯一文本生成 work item。
3. 模型只翻唯一文本。
4. 回填时同源文本复用同一译文。
5. 对带不同 ID 但中文相同的行保留一致译法。

### C. 动态批次大小

不要固定每批 `120` 行。

推荐策略：

- 短 UI/报错文本：`200-300` 行/批。
- 普通系统描述：`120-180` 行/批。
- 长富文本/多 `<br>` 文本：`40-80` 行/批。
- 超长文本：单独批次，避免模型漏行或改 token。

### D. 并发可提高到 6-8

本次使用 `5` 并发，70 批全量 `gpt-5.5` 约 19 分 23 秒。

在不触发限流的前提下：

- `6` 并发预计降到约 `15-17` 分钟。
- `8` 并发预计降到约 `12-15` 分钟。

必须配套：

- 每批独立响应文件。
- 失败批次可单独重跑。
- 重跑时默认跳过已存在且可解析的响应。

### E. QA 后自动局部返修

本次最终有 `22` 条真实结构风险，都是局部行级问题。

推荐固化：

1. hard blocker 输出 `repair_pack.jsonl`。
2. 对 issue 行生成小批次修复 prompt。
3. 要求模型只修这些 key，且必须保留 token 序列。
4. 自动替换响应并重新 QA。
5. 仍失败的行才进入 manual override。
