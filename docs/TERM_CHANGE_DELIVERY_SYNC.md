# 正文用词修改与术语表同步

## 触发与范围

用户确认改名、修改主译，或正文审校修改了需要固定的正式名称时，执行本规范。仅处理用户指定文件、行和目标语言及其对应术语；读取上下文不代表扩大修改范围，不自动全表重译或全量深校。

用户当前确认高于旧术语、旧审校建议和历史缓存。先读取最新实际文件并记录哈希，保留用户已经手动修改的内容，不用上一轮快照覆盖新版本。项目语言区域必须沿用当前确认，例如 pt-BR 不能因风格偏好改成 pt-PT。

## 修改裁决

将本次每项用词变化记录为以下一类，附源文、语言、前后译文及依据：

- 主译更新：用户已确认或源文证据明确，更新正文和实际术语表对应目标格。
- 已有定名补录：修复采用的正式名称未入表，核对正式名称来源后追加；补录数量与新发现错误数量分开报告。
- 语境变体保留：动词与名词、自然变位、单复数及等值编号不能机械替换。每词仍只保留一个主译，不新增斜杠备选。
- 待确认：原文含义或名称来源不明，继续保留疑问，不能猜测写入术语表。

本流程允许用户明确授权的非空主译修改；它不同于翻译前术语补全的默认只补空规则。不要伪装为补空或绕过现有补全凭据检查。实际术语版本变化后重新生成适用的快照与验收依据，仅重检受影响范围，保留未受影响的已验收结果。

## 定词与自然词形

例如用户指定 Construction 改为 Build 时，属性名和道具名可分别使用 Build Speed Boost、Build Speedup；说明句按语境使用 build、building、built 或调整句式。不能只做整表字符串替换，也不能让旧审校理由再次把批准用词改回去。

其他语言同步的是同一含义与项目约定。西语 Construcción、葡语 Construção 是 Construir 的正常名词形式，不能为显示“已修改”强行换成动词。明确区域要求继续约束这些语言。上述例子不是所有项目的默认术语，不得将客户词表或专名硬编码到通用检查器。

## 交付验收清单

1. 保存本次源文件和术语表哈希、范围、语言区域及裁决记录；ID 只负责定位。
2. 将已确认的主译更新和补录写入实际术语 XLSX，保留原 ID、中文、非目标列、原有手动修改及未受影响样式。仅更新缓存、提示词或审校快照不算完成同步。
3. 同步修正正文修改理由和术语使用说明，删除要求恢复旧主译的过时结论；需要追溯的旧理由留在过程记录。
4. 从成品回读核对正文与术语对应关系、修改前后、数字、时长、次数、条件和程序标签。适用的正式质量门禁使用本次术语文件，不自动发现旧版本。
5. 核对所有非目标值及原有标黄未意外变化，成品按项目要求普通打开并回读。失败后只修失败范围并重做相关验证。
6. 交付修复正文、同步后的术语表及变更清单，清楚报告主译更新数、补录数、各语言修改数、待确认项和验证边界。明确下一任务使用的术语版本。

## 生效边界

本文件是执行规范和人工验收清单，不是新增 CLI 自动门禁，也不证明网页产品已接入自动同步。不得仅凭文档提交宣称全仓代码回归或自动语义校对已完成。
