## 本次暴露的问题

### 1. 空目标列需要先走翻译启动管线

这批表的英文列实际是中文拷贝，不是可用译文。直接进入质检只能发现大量中文残留，不能产出最终译文。流程应在预检阶段判断目标列状态：

- 目标列为空或接近全空：启动备用翻译管线。
- 目标列是源文拷贝：视为全量重翻。
- 目标列已有真实译文：进入正常机审和收口。

### 2. 换行有两种形态，必须都保护

表里同时存在真实换行和字面量 `\n`。翻译端点会把字面量 `\n` 吞成空格，导致导入后 UI 文案结构变化。流程需要把两种换行都作为结构约束处理：

- 真实换行：保留为真实换行。
- 字面量 `\n`：保留为字面量 `\n`。
- 翻译时按段处理，再按原分隔符拼回。

### 3. UI 压缩不能生成不可读缩写

为了满足 UI 长度，自动压缩器曾生成 `PCPEEF`、`Shad prel` 这类不可读内容。后续必须新增可读性 gate：

- 禁止未经白名单的全大写首字母串。
- 禁止截断词根，例如 `prel`、`buil`、`queu`、`notif`。
- UI 压缩只默认允许稳定游戏缩写，例如 `Lv`、`HP`、`ATK`、`DEF`、`DMG`、`PVP`、`PVE`、`VIP`。
- `Rwd`、`Req`、`Acct`、`Tmrw`、`OC`、`Mod` 不再默认视为安全缩写，除非项目术语表明确允许。
- 超框时优先改写为短句，不直接截断单词。

### 4. 术语告警和硬错误需要分层展示

本次报告里仍有大量 `term_missing`、`term_partial_hit`、`pattern_inconsistency`。这些主要来自泛词术语、旧译法或语境不同，不应和阻断类错误混在一起。产品上应拆成：

- 阻断错误：变量、标签、换行、中文残留、UI 超长、乱码/坏缩写。
- 可审校提示：术语建议、风格一致性、短文本观察项。
- 非阻断说明：已因自然性或长度主动偏离术语表。

## 产品改进建议

1. 增加“目标列状态识别”模块，自动判断空列、中文拷贝、真实译文三种状态。
2. 增加“翻译启动管线”，用于空列或中文拷贝列，全量生成初译后再进入主质检。
3. 增加“换行保护器”，同时支持真实换行和字面量 `\n`。
4. 增加“不可读缩写检测”，把全大写首字母串和截断词作为硬错误。
5. 增加“UI 短译词典”，只沉淀项目明确允许且用户可理解的短译；默认白名单保持保守。
6. 把报告拆成“上线阻断 / 需审校 / 仅提示”三层，避免用户被大量软提示误导。
7. 增加“最终版一致性校验”，确保最终文件、`result_en.xlsx`、`report_en.xlsx` 是同一轮产物。
8. 增加“交付备份策略”，客户 workbook 默认备份到私有仓库，不进入公共 workflow 仓库。
