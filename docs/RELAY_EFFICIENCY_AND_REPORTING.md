# 大批量效率与进度回报

## 执行与汇报契约

- 首轮无法完成全部授权范围时，结束回复必须说明：已验收范围、剩余阶段、预计完成区间、当前阻断原因、下一步及下次汇报时间。不能只说“持续进行”。
- 新任务先跑代表性首批，保留结果复用。首批尚无有效耗时样本时明确“正在校准”，给出下一次校准回报时间；不得把请求发送量、缓存命中量当作新完成速度。
- `status --manifest` 返回 `delivery.accepted_progress`，按初译、full 首校、独立二审分别记录本次新验收量、复用量和耗时。模型请求数与目标单元数分开。
- ETA 包括剩余模型阶段及本地 QA/导出/验收预留。未实测阶段借用已测角色速度时会列入 `assumptions`；默认大表本地预留15至45分钟、小表2至6分钟，仅作预算，不是 Excel 验收已通过。
- 等额度、源义裁决等不可控等待不计入有效执行时长；阻断时不给虚假落地时刻，汇报“恢复后还需多久＋等待原因”。新增修订工作或速度显著下降，必须修订预估，不能沿用旧承诺。
- 新 manifest 默认设置30分钟后的 `next_report_at`。首轮未完成即报告，之后按约定时间报告；失败或预计超出已报区间及时报告。用户已有明确截止回报时刻时优先沿用，即使未完成也要回报。
- `record-report` 只在消息实际发出后登记，不代发消息。已授权飞书通知须按对应技能发送并读回；没有外发授权则在当前聊天报告。后续监控的唤醒频率应覆盖约定时刻；不因任务未完成推迟到点回报。
- 新增状态字段不创建自动化或恢复已暂停任务。`native_pipeline_only` 完成只代表原生管线；正式交付仍需项目 publication、Microsoft Excel 普通打开/逐格回读、视觉验收及正式路径证据。

```powershell
py -3 -X utf8 scripts/run_large_text_multilingual_runner.py status --manifest <manifest.json>
py -3 -X utf8 scripts/run_large_text_multilingual_runner.py record-report `
  --manifest <manifest.json> --reason "已报告当前进度、条件ETA及阻断原因" `
  --next-report-at <带时区的下一次汇报时间>
py -3 -X utf8 scripts/run_large_text_multilingual_runner.py queue-status --queue <queue.json>
```

## 避免整队等待

队列使用 `items[].id/state/depends_on/pending_source_ids/blockers`。依赖必须明确记录，不把列表排列顺序自动变成业务依赖。`queue-status` 只提出建议，不启动进程、不修改任务。

1. 先查真实进程、任务锁和最新 manifest；未知状态不视为空闲。
2. 运行中的 API 控制器优先；全项目共用并发4、硬上限5，不额外开控制器抢占。
3. 当前项确需源义裁决且已无 API 工作时，推进已授权、无实际依赖的下一项。待确认格单独隔离，禁止缺行发布。
4. `canonical_complete`、`awaiting_visual_acceptance` 进入本地验收，不重新跑模型。未知状态先诊断；队列 paused/complete 不建议新启动。
5. 失败先定位原因，仅明确修复或取得裁决后 `--retry-failed`。额度停止且进程退出时只做一次最小探测；普通429限流和日额度耗尽分开处理。

## 前移检查与格式保真

- preflight 做模板可逆重组检查，暴露自然语言花括号、全角/混合变量等源格式疑点；由项目决定文字或变量身份，不能自动猜成程序参数或正文。
- 结构化模型输出不再 `.strip()`；标签相邻空格及已有换行保留。程序持有的可读标点按语言策略修复，标签及原有变量字面不改。槽位通过后仍检查完整单元格，空槽、数值重复、结构损坏不能靠补空格放行。
- 初译后生成 `initial_surface_precheck.json`，在 full 审校前查看 UI 长度、缩略语和同表编号系列风险；已有审校模式允许先修旧译。二审后生成 `final_surface_precheck.json`，存在硬阻断时禁止导出。
- 前置检查直接复用正式 harness 的可读性、表面格式、UI 长度、编号/系列规则；按 workbook＋sheet＋物理行＋语言定位，不按业务 ID 单独合并。它不代替 cache-lint、项目术语检查、完整正式 harness 或成品回读。
- 正式术语与长度约束冲突、可搜索账号字面等项目例外，仍需对应当前源文/译文/位置/语言/问题类型的精确裁决凭据。改动后旧凭据失效；不得扩大豁免、删除告警或把候选当验收。
- XLSX 写回按物理行分组，每张 worksheet XML 扫描/拼接一次。只改目标单元，保留原 namespace、属性和非目标字节；CR 用 `&#13;` 防止 XML 自动变 LF。不调用 openpyxl 重建整表来加速。

## 导入前拒绝损坏或截断

- 模型返回 `length` 时丢弃该响应并沿用有界拆包；`content_filter`、拒答、工具调用或显式非正常结束状态停止派发，不把可解析的半成品当验收。兼容未返回结束字段的旧中转，但仍逐格校验覆盖和后续审校，不把缺字段当作完整性证明。
- 响应 JSON 拒绝重复键、NaN 和语言别名冲突；初译、首校、二审及旧 checkpoint 同样检查可存储文本。模板要求槽位集合准确且非空，不遗漏、多收或裁掉首尾空白；历史复用也保留已验收文本边界。
- cache-lint、正式 harness 和普通导入接入 JSON 数据/标签顺序/换行完整性检查。LF、CRLF、CR 不互换；合法变量的语言顺序、长专名和真实 Unicode 文本不靠自动截短解决。
- XLSX 目标超过32767个 UTF-16 单元、含 XML 非法字符/孤立代理项或 `_xHHHH_` 保留字面时，定位失败格并停止，禁止裁剪、删除字符或转成字符串凑通过。保留字面已实测会被 Excel 解码而与 XML 读取结果不同，必须另做明确编码适配；`opaque_payload_preserved` 不能绕过文件载体约束。
- V2 整批写入同盘私有暂存目录，所有文件目标逐格精确读回后才移入正式目录；任何一本失败不留下前几本的半批交付。普通导入也先暂存及读回，再生成最终文件；文本开头 `=` 保持字符串，不转公式。拒绝源覆盖、重复物理格和既有输出覆盖。
- 副作用：异常旧缓存、原来容许的标签修补或行尾归一化可能被拦截，需要定位处理，不能关闭门禁。暂存占用一份候选包磁盘空间；硬中断可能留下 `.translation-stage-*`，它不是交付物。已有工作簿内存读取方式不变，未新增全量常驻副本。
- 本地匿名反向测试覆盖拒答/截断、槽缺失、坏缓存、长文本、标签错序、换行、错误写回、源保护、非目标保留及跨文件失败。实际 Excel 普通模式验证16005目标格；无模型请求、无已完成项目重跑。完整句语义漏译继续由 full 逐句审校与独立二审验收，结构通过不替代语义通过。

### 普通入口与公告补强

- 读取 XLSX/CSV 时保留文本 ID 前导零及 `NA`、`NULL`、`nan` 等真实字面，不使用默认缺失值推断覆盖它们。已有 XLSX 数字 ID 仍保留数字类型。
- 普通导入要求 workpack 与 manifest 行清单、实际源表 ID/源文及格式契约一致；响应齐全后还须验证所有响应确实写入对应行。缺包、空包、删行、改源或重复目标 ID 必须在正式文件和缓存生成前停止。
- 公告响应拒绝重复 JSON 字段和非文本译文，不裁剪首尾空白；中间 XLSX 采用目标 XML 精确写回、暂存及读回，开头等号保持文本。Windows 短时替换拒绝最多尝试3次、总等待不超过0.4秒；持续占用则保留旧文件并失败，不无限等待或重新请求模型。
- 主处理器结果/报告先完成载体校验和精确文本读回，再保存完整归档、更新当前语言的 latest 文件；不删除其他语言结果。结果组装按物理位置一次遍历，不逐行扫描整列 ID。两份 latest 文件是顺序替换，不能把它当成双文件原子事务；替换失败时以已验证完整归档为恢复依据，不能报告成功。
- 更严格绑定会拒绝旧版错误 ID 推断生成的 workpack，须从不变源表重新 prepare，复用响应前重新核对映射；不为兼容坏包放宽验证。主处理器增加暂存、预期文本记录及本地读回开销，仍使用内存 DataFrame，不宣称流式或低内存导出。正式 fixture 全量加入常规回归，防止内联测试与交付 CLI 样本漂移。

## 状态与故障分类

`relay_progress.json` 含 pid、更新时间、实际活跃请求数及 stop_reason；派发、致命失败和回到空闲时立即刷新，其余更新保留节流。manifest 原子写入，读取方不读取半写 JSON。请求日志包含时间、角色和分类，不保存服务错误正文或凭据。

| 阻断类型 | 处理方式 |
|---|---|
| HTTP200业务额度错误、HTTP429日额度错误 | 停止所有模型角色派发、保留缓存；与短期限流退避分开 |
| 模糊源义或中英冲突 | 单独裁决＋QA备注，推进无依赖工作；不猜改 |
| 标签/变量/空白/换行损坏 | 本地结构复现与最小修复；改词义的项仍经模型审校、二审 |
| 数量、时长、否定、阵营等真实错译 | 保留语义阻断，定点修复受影响格，不整表重跑 |
| 正确日期表达、运行时字面等误报 | 窄范围规则或精确凭据，正反测试，不全局关闭检查 |
| UI长度、术语与系列不一致 | 在缓存阶段暴露，先定点收口后一次导出 |
| Excel布局或普通打开失败 | 本地验收修复，不追加无关模型调用，不发布未验收文件 |

## 验证边界

离线模拟测试证明状态、隔离、缓存和错误处理路径，不证明模型质量或实时中转吞吐。真实大表写回基准只计写回算法，不外推整个翻译周期。首批真实 API 的速度仍须在下一次已授权新任务实测；本次维护不重发已完成任务、不启动旧巡检。代码提交推送须获得用户授权；Studio 同步单独执行和验收。

## 交付收口

同批多份需求只保留一个正式交付入口，分用途子目录，最终ZIP放在这个目录内。源需求、当前术语与PB沿用绑定路径；阶段成果与过程文件不冒充最终交付。整理已完成项目时先检查进程，只移动已明确的文件，不覆盖、不删除缓存；移动后直接核对实际内容，更新当前队列和出版路径，保留移动映射及整理前元数据。历史日志、消息正文及缓存输入绑定不重写，旧路径通过映射追溯；不得因整理触发重译、重审或重复外发。
