# 技能名与地名翻译规范

## 适用范围

本规范只对术语表 `分类/category/type` 明确标记的专名生效，不根据中文长度或行内容猜测类型。

- 技能名：`技能`、`技能名`、`技能名称`、`招式名`、`天赋名`、`被动名`、`skill name`、`ability name`、`talent name`
- 地名：`地名`、`地点名`、`地图名`、`区域名`、`场景名`、`place name`、`location name`、`map name`、`region name`
- 不适用：`技能描述`、`技能效果`、`地图说明`、`地点描述` 等句子或说明文本

## 技能名

技能名默认按移动端 UI 名称处理。

- 英语优先不超过 2 个可读单词和 24 个字符，使用自然的 Title Case 名词短语、复合词或必要的连字符。
- 优先删除无必要的 `A / The / Of / To` 和解释性尾巴，不把技能名翻译成完整句子。
- 必须保留核心意象、玩法区分和项目既有命名，不得为了两词目标造成错译、语义变窄或与其他技能重名。
- 只有在两词会破坏含义、自然度或唯一性时才允许更长译名。
- 禁止截断单词、删元音或制造内部代码式缩写。

其他语言不机械套用英语表面词数，优先约 2 个核心语义单位，并服从目标语言的冠词、介词、格变化和自然语序。

## 地名

地名按地图、关卡或场景 UI 专名处理。

- 英语优先不超过 2 个核心词和 28 个字符；`a / an / the / of / in / on / to` 等连接词不计入核心词数。
- 保留地理中心词和核心意象，例如 `Temple`、`Valley`、`Lake`、`Fort`，避免压缩后看不出地点类型。
- 既有世界观专名、历史通行译名和自然结构可以超过软预算，例如 `Temple of the Sun`。
- 不同中文地点不得因过度压缩合并成同一译名。

其他语言同样以紧凑自然为目标，但不执行英语表面词数硬切。

## 工作流行为

1. 术语加载阶段保留 `category`，派生 `name_type`。
2. 翻译 workpack 写入 `name_type` 和 `name_policy`，模型按专名规则初译。
3. 机审和 AI 审校复核技能名词数、地名核心词数及不同中文专名撞名。
4. `skill_name_word_count_watch`、`location_name_compactness_watch` 和 `name_translation_collision_watch` 都是软预警，必须结合语义审校，不做机械替换。
5. 有实质修改后重新跑术语、占位符、中文残留、可读缩写和专名检查，再读回最终 workbook。

## 验收标准

- 明确分类的技能名和地名都进入专名策略，不误处理描述句。
- 英语超预算项完成逐项审校；保留超预算译名时有明确的含义、自然度或唯一性理由。
- 不出现不可读缩写、截断词、核心意象丢失或不同专名误撞名。
- 术语主译、正文译文和最终 workbook 读回结果一致。
