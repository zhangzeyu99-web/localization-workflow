# 翻译前术语完善

## 触发与边界

用户要求完善术语，或本批发现词典外稳定专名/系统名时，先执行本流程，再进入正文翻译。术语表内已有中文但目标译文为空，也不能视为术语已准备完成。只补本项目，不跨项目混用；不要依赖固定线程ID或手工复制候选。

只处理本批指定范围及命中的必要术语缺译，不自动重译整份词典、重开已完成任务或扩展目标语言。本规范不新增源表覆盖、远端回填或 Git 推送授权；已有非空主译的授权调整另按 `TERM_CHANGE_DELIVERY_SYNC.md` 执行，与默认补空、追加分开。

术语提取源负责候选发现、证据和价值筛选；本地化源负责候选裁决、缺译补全、术语表验收和正文翻译。不自动收录所有短中文、完整句、临时状态或数值变体；句内专名同样需要检查。模型候选不是已批准术语。

## 语言与名称

- 按实际表头映射语言，不按固定列号；规范语言代码优先于兼容别名。同时存在 `ID` 和 `IDN` 时，`ID` 是词条标识，印尼语读取 `IDN`。旧读取器若误选列，先修正映射或使用真实术语的规范列快照，不改客户表头或删语言列凑验收。
- 官方和已批准英语优先原样复用，缺译再补；其他语言的术语补译与批准英语对齐，并用中文复核语义。语言地区沿用各项目约定，不将某个项目的地区规则扩展到所有项目。正文仍按本批明确源模式处理，存在英语列不等于授权切换主源。
- 每语言只保留一个简洁主译，不写 `A / B`；按显式分类执行 `UI_NAME_TRANSLATION_STANDARD.md`。技能、地点、建筑名的两词和长度要求是软约束，核心含义、自然度及唯一性优先；不压缩描述句，不机械截断或用坏缩写。正文保留自然词形和语境，不全局机械替换。

## 执行

默认只走三个业务阶段，以下 CLI 是阶段内接口，不是追加多轮模型审阅：

1. **术语一次定稿**：只读实际源表，调用提取 CLI；主控一次合并判断收录价值、补译和校对，验收后固定版本。模型只读 `request.json.review_packet`，完整候选和证据留本地。已拒绝项不重复送模型；裁决文件合并本轮结果与原有拒绝记录，候选全集验收不减少。已有术语默认只补本批命中的缺译，不把整个旧词典的空列顺便重译。
2. **正文翻译及合并校对**：直接用正式 runner，不另造低容量批处理入口。基础校对把语义、术语、UI长度和结构衔接合在同一轮；程序 QA 先收齐问题，模型只复核疑点。确实要求全量深校时仍按原覆盖与二次纠偏规则执行，不得减少范围。已经通过的同版本结果复用，补修只检查受影响的行和语言。
3. **一次导出验收**：所有缓存级检查、普通 harness 规则和建议裁决在导出前收口，再导出、普通打开和读回。最终实际载体检查不可省略；若读回发现新问题，只修该问题，不借机重审整表。

收录价值：跨文本需要固定叫法的专名、核心机制、货币和易混淆概念可入表；有分类、短、出现多次都不能单独作为批准依据。普通按钮、临时提示、已有词根可组合的名称默认留在本批译文缓存；需要入表时给出项目语境理由。一次出现的正式技能/角色名可以收录，不按频次或数量配额砍词。此前已交付术语不自动回删。

效率边界：沿用现有默认 `batch_size=60 / max_batch_chars=24000` 和小批 smoke；只在实际响应截断、超时等证据出现后拆失败批，不预先把所有文本缩成极小批。不设置额度/时间硬上限，不降低模型、目标语言或必要校对范围；耗时上涨先看重复覆盖、上下文体积、批次碎片化和失败续跑。入口开发及全仓测试与每批翻译分开，不反复“边交付边造流程”。

## 接口参考

1. 读取需求表实际行数、语言列、最新术语表和项目资料，不能把旧Brief的规模当成本批覆盖数。
2. 通过稳定CLI调用术语工作流并生成待审请求：

```powershell
python scripts/run_glossary_preflight.py prepare --input <需求.xlsx> --term-base <原术语.xlsx> --target-langs EN,FR,DE,PT,ES,TR,RU --glossary-workflow <术语提取源目录> --work-dir <项目_work/批次/glossary_preflight>
```

术语工作流提供 `scripts/export_glossary_candidates.py`。参数为可重复的 `--input`、`--existing-glossary`、`--target-langs`、`--output`。跨仓库通过JSON文件和子进程连接，不直接导入另一仓库内部模块，也不启动新的永久任务。

候选检查必须覆盖独立名称、句内引号和【名称】（包括颜色标签包裹的名称），不能只扫描整格短文本。跨仓库子进程启动前统一把任务相对路径解析为绝对路径，避免从提取源目录误读文件。

3. 审阅每个候选并记录include/reject及依据；needs_context不能静默通过。已有官方译文优先复用，缺少译文再翻译校对。名称按显式分类应用简洁规范，正文允许自然词形。
   若句内审阅补出了原候选以外的词，使用提取器约定的`review_file`结构记录真实源行证据，再以`prepare --review-file <review_decisions.json>`重新导出完整候选与请求。不得跳过候选全集覆盖验收。
4. 更新副本：保留原ID、中文、顺序、非空译文和分类；原行允许目标语言补空，新候选仅追加。旧词典中的未决冲突不得靠覆盖消除。
5. 对补全术语逐项语义与结构校对、读回后，生成验收凭据：

```powershell
python scripts/run_glossary_preflight.py accept --request <request.json> --reviewed <reviewed_candidates.json> --updated-glossary <补全术语.xlsx> --output <receipt.json>
```

6. 正文runner必须引用同一补全术语和凭据：

```powershell
python scripts/run_large_text_multilingual_runner.py run --input <需求.xlsx> --term-base <补全术语.xlsx> --glossary-receipt <receipt.json> --target-langs EN,FR,DE,PT,ES,TR,RU --task-dir <项目批次工作目录> --relay-config <私有API配置> --proofread-mode basic
```

未明确要求深校时用basic；明确要求后才用sampled/full。长结构文本继续使用程序文本槽机制，不把JSON、标签或占位符交由模型保留。

## 旧版归档

每次更新术语，完成新表语义校对、真实成品读回以及所有仍引用旧路径的任务后，将已被新表取代的根目录旧版本移入 `_archive/glossaries/<时间戳>/`；根目录每个术语系列只留当前维护版。默认不删除。不要仅凭日期挑新版，不把其他项目或独立语言表当旧版，也不清理历史交付和 `_work` 快照。归档表不参加默认术语发现。

按明确的新版/旧版绝对路径、已验收内容和版本预览归档；移动前验证目标仍在项目指定目录内，使用原生文件操作仅移动显式旧文件，移动后读回实际内容并保存路径清单。不调用模型、不重译、不删除文件，不主动计算或登记额外哈希；要求额外哈希的旧 `run_glossary_archive.py` 不作为默认入口，工具内部凭据完整性机制保留。无法安全归档时保留旧文件并说明待处理。

语义验收仍由上游负责。归档后同步项目 PB 和当前任务配置中的维护版路径，不改历史记录。同名覆盖维护时，必须在覆盖前将旧内容备份到归档，保留失败恢复能力；不要把已经覆盖后的新文件当旧版归档。新文件名版本可在验收后按显式旧文件路径归档。

不能在 `accept` 后、正文运行前移动旧表，因为正文凭据仍核验旧路径。历史重跑先按归档清单定位原版并重新生成与真实路径一致的凭据，不自动换用当前新版。此为 Agent 收口必做步骤，未在 `accept` 内自动移动文件，未同步 Studio。

## 门禁

- 工具内部将源表、原术语表、候选、裁决和更新术语绑定到验收凭据，正文 API 启动前复核，任何漂移中止；不要求 Agent 另行计算或登记散列清单。
- 每个原候选必须有最终裁决，所有include必须与追加词条一一对应且目标语言齐全；reject须有理由。
- 本批命中的已有空译术语必须补齐目标语言；追加词条分类必须与审阅分类相同，不能仅因中文已在表中就放行。
- 原中文、ID、顺序、分类和非空译文不可改；只允许原目标语言空格补空，防止顺手重译旧词典。
- 未传凭据的旧runner路径保持兼容；一旦本任务触发术语完善，不得通过省略参数绕过验收。凭据记录进入正文manifest的glossary_enrichment阶段。
- 代码门禁验证结构与版本，不证明词典已覆盖所有语义，也不能替代术语语义校对。正文中再发现遗漏时，先回到术语阶段补证据并重新验收，不得只在正文临时造名。
- 补提取后只重新检查受影响正文和术语映射；保留已通过缓存，不因更新凭据就把成功内容整包重译。代码密集正文需检查重新拼合后的语义衔接，结构一致不能代替语义正确。
- 成品和补全术语放项目交付目录；候选、裁决、请求和凭据留在项目_work。源文件不覆盖，客户数据不进公开仓库。
