# 备注为修改的词条：语义复核与重译

## 触发条件

备注、状态或变更类型明确标为“修改”的行，所有本次目标语言必须逐条重新核对当前源文的语义。该规则优先于同ID复用、历史整句优先、保留已有译文和同版本缓存跳过等通用规则。

## 默认处理

- ID/Key只用于稳定定位、版本对照和写回，不能证明新旧中文含义一致；禁止只凭同ID带入旧译。
- 输入必须以当前中文为准，核对删词、改名、主体、动作、条件、等级、数量、时间、因果和指代。历史译文只作待核实证据，不能自行提升为已批准答案。
- 若用户要求抛弃旧译、全部重译或从当前源文重译，初译输入必须移除旧译、旧英语参考、历史句库和旧任务翻译缓存；当前术语及已批准独立专名仍可作为约束。ID保留原值，不重新编号。
- 所有修改行和目标语言均需显式记录KEEP/FIX/FLAG及语义依据。无记录是未审，不得当作KEEP。
- 二次核对覆盖全部修改行，包含第一轮KEEP；只校验“审计集合等于建议修改集合”不足以证明审校覆盖。
- 源文、译文或上下文变更后，对应审校记录失效；其他已通过单元格不重复重审。
- 其他语言不能直接继承未经当前中文验证的英语含义。英语和中文发生冲突时，按用户指定主源裁决；当前中文重译任务以中文为主。

## 程序与交付边界

- 保留物理行、ID、中文及备注；只更新指定目标语言，实际改动单元格标黄。
- JSON、富文本结构由程序固定，复杂结构只给模型纯文本槽，模型不重建代码结构。
- 写回前检查修改行数×目标语言数与语义记录一一对应，拒绝缺行、重复、错位、旧源文指纹和未决FLAG。
- 占位符、数字、标签和乱码门禁独立执行；这些检查通过不等于语义正确。
- 交付必须核对未选中行及非目标列不变、最终译文与缓存一致、普通打开和真实读回。QA分别记录重译覆盖、语义复核覆盖、实际改动和剩余问题。

## 反例与验收

“旧资源名→新资源名，但目标仍为旧资源名”必须进入语义复核；“源文未变且译文可靠”不应因同一文件内别的行修改而重新处理。礼包删掉币种限定后不能继续增加币种，活动改名必须同步核对活动名、币种、说明及邮件，不能只修一处标题。

该文档约束维护源Agent执行流程，不代表所有历史临时脚本或下游Studio已经自动升级。
